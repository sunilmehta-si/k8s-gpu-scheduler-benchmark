# Contributing

Thanks for helping make GPU scheduling decisions less of a guess. The most valuable contributions are new stacks,
real-world traces, and cluster runs that check (or break) the model.

## Set up

```bash
git clone https://github.com/sunilmehta-si/k8s-gpu-scheduler-benchmark && cd k8s-gpu-scheduler-benchmark
python -m venv .venv && . .venv/bin/activate && pip install -e .
make test
```

## House rules

- **Verify, don't recall.** When you add or change a stack, take API versions, field names and install commands from
  that project's own repository or docs at a pinned version, and say which in the commit message. (Kueue renamed
  `cohort` to `cohortName` in v1beta2; kwok's jitter delay is an upper bound. Both would have been wrong from memory.)
- **Check behaviour against placements, not only totals.** A model can match a real run's time to finish for the
  wrong reason. Compare where pods actually ran (`gsb timeline`, `gsb compare`) before trusting a preset. Volcano's
  first preset assumed it bin-packed GPUs; the real placements showed it stacks pods by count.
- **Label what is modelled.** Simulation results say `"mode": "simulation"`, cluster results `"mode": "cluster"`.
  Never present one as the other, and keep every modelling choice traceable to a documented behaviour in
  [`presets.py`](gpu_sched_bench/presets.py).
- **Results are code.** Anything under `results/` is regenerated by `make results` and checked by the tests, so a
  change that moves the numbers must commit the new numbers, and the README must match them.
- One logical change per commit, with a message that says what and why.

## Add a scheduling stack

1. **Model it:** add a preset in [`presets.py`](gpu_sched_bench/presets.py) built from the stack's documented
   defaults, with a docstring line per behaviour and its source. If a behaviour needs a new knob, add it to
   [`sim/policy.py`](gpu_sched_bench/sim/policy.py) and the engine, with tests in `tests/test_sim_engine.py`.
2. **Render it:** add `<stack>_setup` and `<stack>_workload` in [`manifests.py`](gpu_sched_bench/manifests.py)
   and register them in `STACKS`. Pods must keep the kwok delay annotations from `pod_template`.
3. **Install it:** add `scripts/install-<stack>.sh` with a pinned version that waits until the scheduler and its
   webhooks are ready, and add the stack to the matrix in [`.github/workflows/cluster.yml`](.github/workflows/cluster.yml).
4. **Prove it:** the cluster workflow must pass with `--strict`, and `gsb compare` should show where the model and
   the real scheduler differ. Explain large differences in the pull request.

A **tuned variant** is the same stack with one setting changed (for example `volcano-binpack`). Add its name to
`TUNED` in `presets.py` (the preset is the base stack with the changed knob), its scheduler configuration to
`SCHEDULER_CONFIG` in `manifests.py` (`gsb manifests --part scheduler` renders it), and an install script that
installs the base stack and then applies that configuration.

## Contribute a trace

Traces are JSONL, one job per line (see [`trace.py`](gpu_sched_bench/trace.py)). Anonymise team and model names,
keep arrival times relative, and describe the source and time window in `traces/README.md`.

## Security

Please report vulnerabilities privately through GitHub's **Security → Report a vulnerability**, not in public issues.
